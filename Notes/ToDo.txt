1) Boundary conditions need some structural adjustments to how they function. In particular, the issue
is how different boundary conditions interact at the edges. I don't want to have to write hybrid classes
for all the different combinations of boundary conditions that can arise. It would be better to have
a way of doing this automatically. Boundary conditions are currently given priority depending on there type
which is sufficient for 1 grid point thick boundaries (see point below).

2) Stencils larger than 3-point should be easy to include for the gradients, but I have not written the
Wilson loops in the same generalisable manner. It would be good to include this.

3) Parallelisation needs to be included. The general idea is to have this effectively handled by an
"interior" boundary condition class, with a copy of lattice and all that entails for each process.

4) It would be nice to have a way to normalise the potential energy of the double SO(N) class internally
for general parameter choices. This can be done once at set-up and stored to be used during evolution.
This is quite a difficult problem, so there is currently the option to enter the normalisation manually
(to be added).
